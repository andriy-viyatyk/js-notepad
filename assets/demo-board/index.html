Persephone Boards

A living demo & reference — what a board is, how to theme it, what it can do, and how to build one.

What is a Board?

A Board is a small local application whose UI you own as a plain HTML page, backed by scripts you write in any language. Persephone hosts the page in a sandboxed webview and injects a single bridge object, window.persephone. Persephone owns no board state and no board UI — it just wires the bridge and shows the page. A board lives in its own folder under .persephone/boards/<Name>/.

How it works — frontend + backend + a channel

  • Frontend — index.html + app.js (+ any CSS/assets). Owns all UI and all state. This is what renders in the webview.
  • Backend — scripts under scripts/ (.js, .py, .ps1, .sh, …). They run as real OS processes with your privileges and talk to the page over stdout.
  • Channel — persephone.execute(commandLine). The page calls a script, the script prints to stdout, the page reads it and renders. That's the whole loop.

Built by an agent, not by hand

Boards are meant to be authored by an AI coding agent — Claude Code, for example — rather than hand-written. There's deliberately no in-board editor, debugger, or dev console: the host stays minimal on purpose. And a board is made of exactly what an agent is best at — raw HTML, vanilla JavaScript, and Node or Python scripts — so the fastest way to build one is simply to ask.

Describe the report, tool, or mini-application you need, and your agent scaffolds the page, wires persephone.execute() to a backend script, and themes it with the --p-* variables — usually in a few minutes. You review the result and refine it in plain language.

    Theme with the --p-* contract

    Persephone injects its palette as CSS variables on <html> and keeps them live across theme switches. Style everything with them and your board matches the app automatically — switch the app theme (dark ↔ light) and watch this whole page restyle live, with no JS.

    body { background: var(--p-bg); color: var(--p-text); }
    button { background: var(--p-accent); border-radius: var(--p-radius-md); }

    Colors update with the theme; metrics (--p-space-*, --p-radius-*, --p-font-*) are constants. Also mirrored in JS as persephone.theme / persephone.tokens / persephone.onThemeChange(cb) — for colors you set from JS.

    Anatomy of a board

    • index.html — your page. Edit it and the board reloads automatically.
    • app.js / style.css — your logic and styling (reference relatively, e.g. ./app.js). After editing these, click Refresh in the Boards side panel to remount.
    • scripts/ — backend scripts in any language, invoked via persephone.execute("scripts/thing.js"). cwd defaults to the board folder, so relative paths just work.

    Returning data reliably

    A bare getJson() assumes stdout contains only your JSON. The moment a script shells out to a tool that prints its own output, that breaks. Two habits fix it:

    • Logs → stderr, result → stdout. Send diagnostics to stderr; capture sub-tool output instead of letting it flow through.
    • Wrap the result in a marker and extract it: emit "@@RESULT@@" + JSON.stringify(x) from the script, then read it with execute(cmd).getJson(/@@RESULT@@(.*)/). It extracts the match before parsing and still rejects on a non-zero exit with the captured stderr.

    Debugging a board with an AI agent

    A board has no built-in editor or dev console — you debug it the same way you build it: through an AI agent connected to Persephone's MCP server. The agent reads the live page, clicks and types, and runs JavaScript inside the board, using the Playwright-style browser_* tools pointed at the board's page.

    1 · Enable the MCP server in Persephone

    Open Settings → MCP Server and:

    • Check Enable MCP server (off by default).
    • Check Enable browser interaction — required for the browser_* tools that drive a board.
    • Leave the Port at 7865 (changing it requires toggling the server off and on).

    The server listens on http://localhost:7865/mcp. A Copy Config button there gives you the ready-to-paste snippet below.

    2 · Point your agent at it

    The transport is HTTP (not stdio). For Claude Code, add to .mcp.json (project root or ~/.claude/.mcp.json):

    {
  "mcpServers": {
    "persephone": {
      "type": "http",
      "url": "http://localhost:7865/mcp"
    }
  }
}

    Claude Desktop: add an MCP server named persephone with the same URL. After enabling browser interaction, reconnect the agent so it picks up the new tools.

    3 · Open the board, then drive it

    You (the human) open the board first — an agent cannot open boards, and an untrusted project won't render. Then the agent:

    • list_pages → find this board (editor: "board-view", with its selectedBoard) and read its pageId.
    • browser_snapshot { pageId } → read the accessibility tree (element refs).
    • browser_click / browser_type / browser_press_key → interact, using refs from the snapshot.
    • browser_evaluate { pageId, function } → run JS in the page: inspect state, read --p-* values, poke the DOM. The most useful probe when something looks wrong.
    Always pass pageId — without it the browser_* tools target the active browser page, not your board. Navigation and tab tools don't apply: a board is one fixed page.

    Tips

    • Editing index.html reloads the board automatically; after editing app.js or CSS, click Refresh in the Boards side panel to remount.
    • Failures reported via persephone.notify(msg, "error") are toasted and appended to the board's ui.log — check there first when a board misbehaves.
