# US-821: Update Electron to 43.0.0 (Castlabs +wvcus)

**Epic:** [EPIC-040 — Dependency & Platform Updates](../../epics/EPIC-040.md)
**Status:** In Progress

## Goal

Upgrade the Electron runtime from `v39.8.0+wvcus` (Chromium 142 / Node 22) to the latest stable
Castlabs fork `v43.0.0+wvcus` (Chromium 150 / Node 24), keeping Widevine DRM intact, and verify
no functional regressions across build, editors, browser, scripting, boards, and DRM playback.

## Background

### Why Castlabs, and why the exact tag matters

Persephone does **not** use upstream Electron. It uses the [Castlabs ECS fork](https://github.com/castlabs/electron-releases)
which bundles the Widevine CDM and supports VMP signing — required for DRM playback (Netflix,
Disney+) in the built-in browser. The `+wvcus` suffix = **w**ide**v**ine + **c**omponent-**u**pdate-**s**erver
(US region). **Every** newer Castlabs tag keeps `+wvcus`, so DRM survives the upgrade.

The dependency is a **git URL**, not a semver range:

```jsonc
// package.json (devDependencies)
"electron": "https://github.com/castlabs/electron-releases#v39.8.0+wvcus"
```

electron-builder downloads the matching prebuilt binary via a mirror override:

```yaml
# electron-builder.yml
electronDownload:
  mirror: "https://github.com/castlabs/electron-releases/releases/download/v"
```

The mirror line does **not** change — it already points at the Castlabs releases; only the
version tag in `package.json` moves.

### Version jump

| | Current (39.8.0) | Target (43.0.0) |
|---|---|---|
| Chromium | 142 | 150.0.7871.46 |
| Node.js (bundled runtime) | 22.x | 24.17.0 |

This is **4 Electron majors / ~8 Chromium majors / one Node major**. The Node bundled-runtime
jump (22 → 24) affects the **main process, preload scripts, and the renderer** (which runs with
`nodeIntegration: true`). Build tooling on the CI host is separate (see CI note below).

### How the runtime is wired (files that matter)

| File | Role in the upgrade |
|------|---------------------|
| `package.json` | The `electron` git-URL tag — **the one required edit**. |
| `package-lock.json` | Regenerated by `npm install` after the tag change. |
| `electron-builder.yml` | `electronDownload.mirror` (Castlabs) + `afterSign: scripts/vmp-sign.mjs` (VMP). No edit expected. |
| `scripts/vmp-sign.mjs` | VMP-signs the Electron binary via Castlabs EVS. Version-agnostic; no edit expected. |
| `forge.config.ts` | `FusesPlugin` (via `@electron/fuses` 1.8.0) + `VitePlugin`. Verify fuses still apply on E43. |
| `scripts/build-prod.mjs` | Vite build for main/preload/renderer. Renderer target `esnext`. No edit expected. |
| `.github/workflows/publish.yml` | CI build. `node-version: 20` on the build host + `npm install` + `VMP_SIGN=true`. See CI note. |
| `patches/monaco-editor+0.52.2.patch` | Unrelated to Electron — no impact. |

### No native Node addons

Persephone ships its native code as **separate Rust binaries** (`persephone-launcher.exe`,
`persephone-snip.exe`, `mneme.exe`) spawned as child processes — not as N-API/node-gyp addons
loaded into Electron. `rebuildConfig: {}` in `forge.config.ts` is empty. This removes the single
biggest Electron-upgrade risk (ABI-incompatible native rebuilds). The Rust binaries are process
children and are unaffected by the Electron/Node bump.

### Security-sensitive webPreferences (unchanged by default, but verify)

- Main/child windows (`src/main/open-window.ts:52-57`): `nodeIntegration: true`,
  `contextIsolation: false`, `webviewTag: true`, `nodeIntegrationInSubFrames: false`.
- `<webview>` guest preload (`src/preload-webview.ts`): default `contextIsolation: true`; uses
  `contextBridge.executeInMainWorld` (the US-813 `window.chrome` shim). **Confirm
  `executeInMainWorld` still exists and behaves the same on E43** (it is newer API surface).
- Custom protocols: `protocol.registerSchemesAsPrivileged` (`src/main/main-setup.ts:29`),
  `protocol.handle` for `app-asset` / `safe-file` (main-setup) and `board` (board-protocol-service).
  Protocol API has been stable since E25; low risk but part of the smoke test.

## Implementation plan

> Do this on a dedicated working branch, **not** on `main` and **not** on the shared
> `upcoming-vX.Y.Z` release branch — an Electron major is large enough to isolate. Suggested:
> `upgrade/electron-43`.

### Step 1 — Read the upstream breaking changes (before touching code)

Read Electron breaking-changes docs for majors **40, 41, 42, 43** (cumulative):
`https://www.electronjs.org/docs/latest/breaking-changes`. Focus on anything touching APIs the
app uses: `BrowserWindow`/`webPreferences`, `session`, `protocol`, `<webview>`,
`webContents`, `contextBridge`, `Menu`, `dialog`, `nativeImage`, `utilityProcess`,
`app` events, and any Node 24 removals affecting main/preload code. Record hits in the
"Concerns" section below before editing.

### Step 2 — Bump the dependency

In `package.json`, change:

```diff
- "electron": "https://github.com/castlabs/electron-releases#v39.8.0+wvcus",
+ "electron": "https://github.com/castlabs/electron-releases#v43.0.0+wvcus",
```

Then:

```bash
npm install        # regenerates package-lock.json, downloads the E43 binary
npx electron --version   # expect: v43.0.0
```

### Step 3 — Align build tooling (only if Step 1/build surfaces a need)

- `@electron-forge/*` — bump 7.10.2 → **7.11.2** (already the "safe batch" target; newer Forge
  is friendlier to newer Electron). Do this here if E43 + Forge 7.10.2 misbehaves in `npm start`.
- `@types/node` — currently `^20`. The bundled runtime is now **Node 24**. Bump to `^24` so
  main/preload typings match the runtime. Verify `npm run typecheck` stays clean (it may surface
  newly-typed or removed Node APIs — fix any fallout).
- `.github/workflows/publish.yml` — the CI **build host** uses `node-version: 20`. This is the
  Node that runs `npm install` + electron-builder, independent of Electron's bundled Node. E43 /
  electron-builder 26.15 may require a newer build host; if the CI build fails, bump to
  `node-version: 22`. (Leave unchanged unless CI fails.)

### Step 4 — Verify @electron/fuses compatibility

`forge.config.ts` sets six V1 fuses via `@electron/fuses` 1.8.0, including
`EnableEmbeddedAsarIntegrityValidation: true` and `OnlyLoadAppFromAsar: true`. Confirm fuses
still flip on the E43 binary. If 1.8.0 can't parse the E43 binary, bump `@electron/fuses` to 2.x
(otherwise leave it — the 1→2 major is a *deferred* item in the epic and shouldn't be pulled in
without cause).

### Step 5 — Dev smoke test (`npm start`)

Launch and exercise the surfaces most exposed to a Chromium/Node jump:

- App boots; main window renders; no console errors on startup.
- **Editors**: Monaco (open a code file), grid (JSON/CSV), markdown preview, PDF, notebook,
  draw/excalidraw, video/audio player.
- **Built-in browser**: open a normal site; **Google sign-in still works** (the US-813
  `window.chrome` shim via `contextBridge.executeInMainWorld` must still inject) — this is the
  single most important browser regression check.
- **Scripting**: run a script using `page`, `app`, `io`; confirm the worker
  (`WorkerRunner`/`worker-host`) runs.
- **Boards**: create the demo board, open it, confirm the `board://` protocol serves and the
  bridge shim connects.
- **Browser automation / CDP**: run a `browser_*` MCP tool; confirm on-demand debugger attach
  (`cdp-service.ts` `ensureAttached`) still works on E43.
- **Custom protocols**: `app-asset` / `safe-file` / `board` all resolve.

### Step 6 — Production build

```bash
npm run dist            # electron-builder NSIS + ZIP, VMP signing skipped
```

Confirm the installer builds and the packaged app launches. If EVS credentials are available
locally, run `VMP_SIGN=true npm run dist` and confirm VMP signing succeeds against the E43
binary.

### Step 7 — DRM verification (the reason we're on Castlabs)

In a VMP-signed build, open a Widevine-protected stream (e.g. Netflix / Disney+ / Spotify web
player) in the built-in browser and confirm **licensed playback works** — not just that the page
loads. This is the definitive check that `v43.0.0+wvcus` + VMP signing is intact. If a signed
local build isn't feasible, defer this to the CI-produced tagged build and gate the epic-close on
a real post-release DRM check.

### Breaking-changes triage for E40 → E43 (already checked against our code)

Most upstream breaking changes **do not apply** to Persephone (Windows-only target; renderer
already uses web APIs). Verified findings:

| Change (version) | Applies? | Evidence |
|------------------|----------|----------|
| Dialog `defaultPath` defaults to Downloads (43) | **Low** — all dialog callers pass an explicit `defaultPath` (`src/ipc/main/dialog-handlers.ts:16,39,55`, `src/main/download-service.ts:92-96`). Only affects calls that omit it. | grep confirmed |
| `session.clearStorageData` `quotas` removed (42) | **No** — our two calls pass no `quotas` (`src/main/browser-service.ts:624,633`, only `{ storages: [...] }`). | grep confirmed |
| `clipboard` renderer access deprecated (40) | **No** — renderer uses `navigator.clipboard`, not Electron's `clipboard` module. | grep confirmed |
| `nativeImage.toBitmap()` sRGB normalization (43) | **Low** — `toBitmap()` not called; `snip-service.ts` uses `nativeImage` for PNG data-URLs only. | grep confirmed |
| `webPreferences.offscreen` scale-factor (42) | **No** — offscreen rendering not used. | grep confirmed |
| PDFs no longer separate WebContents (41) | **Low** — PDF viewer uses bundled pdf.js, not Chromium's PDF WebContents. | verify |
| Linux rounded corners / WCO / `showHiddenFiles` (41/43) | **No** — Windows-only build (`win` target). | n/a |
| macOS `UNNotification` code-signing (42) | **No** — Windows-only. | n/a |
| **`electron` npm no longer downloads binary via postinstall (42)** | **Verify** — install now downloads the binary "on first execution"; `ELECTRON_SKIP_BINARY_DOWNLOAD` is gone. Confirm `npm install` in CI (`publish.yml`) and `electron-builder`'s mirror download still resolve the E43 binary. | **check in CI** |

## Concerns / Open questions

- **Node 24 in main/preload/renderer.** Node 22 → 24 can remove/replace APIs. Grep the main
  process and scripting layer for anything Node-version-sensitive; run `npm run typecheck` after
  bumping `@types/node` to 24 and fix fallout. *(Record specific breaking-change hits from Step 1
  here before implementation.)*
- **`contextBridge.executeInMainWorld` on E43.** The US-813 Google-sign-in shim depends on it.
  Confirm the API signature is unchanged and the shim still injects at document-start in the
  guest main world. This is a hard gate — regressing it re-breaks Google sign-in.
- **VMP signing on a newer binary.** `castlabs-evs` (pip) must support signing the E43 binary.
  CI pins `python-version: 3.12` + `pip install castlabs-evs` (unpinned → latest). Verify EVS
  latest signs E43; if not, this blocks release.
- **Persistent DRM licenses removed.** The E43 Castlabs notes state persistent Widevine licenses
  are no longer supported by Chromium on any platform. Persephone doesn't rely on persistent
  licenses (session playback only), but confirm nothing in the browser flow assumed them.
- **CI build-host Node.** Only bump `publish.yml` `node-version` if the CI build actually fails —
  don't pre-emptively change it.
- **Fuses major (`@electron/fuses` 1→2).** Only pull in if 1.8.0 fails on E43; otherwise it stays
  a deferred epic item.
